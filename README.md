# NoSqlLab2

## Уведомления о заявках

`POST /api/lead` увеличивает счётчик Riak и сохраняет событие `CREATED` в ScyllaDB. Затем приложение отправляет уведомление в открытые WebSocket-сессии пользователя. При сбое сохранения уведомления API всё равно возвращает номер, уже выданный Riak.

Подключение к `/ws/notifications` использует действующую HTTP-сессию (`JSESSIONID`) и origin приложения. Пример сообщения от сервера:

```json
{"type":"NOTIFICATION","notificationId":"6b7b037d-d7a2-4b61-9923-3abd8159badf","attemptId":"4731a6ae-1a69-4cad-ade5-cd1e6dfe21e8","message":"Заявка №42 принята"}
```

Клиент обрабатывает сообщение, затем отправляет подтверждение:

```json
{"type":"ACK","attemptId":"4731a6ae-1a69-4cad-ade5-cd1e6dfe21e8"}
```

Сервер отвечает `ACKNOWLEDGED` после записи `DELIVERED` в ScyllaDB. `ACK_RETRY` означает, что клиент может повторить подтверждение с тем же идентификатором. `INVALID_ACK` означает, что подтверждение в таком виде принять нельзя.

- При отсутствии активной сессии или ошибке отправки сохраняется `FAILED` с причиной.
- Если ACK не пришёл за `notifications.websocket.ack-timeout` (по умолчанию 10 секунд), сохраняется `UNCONFIRMED`. При позднем ACK история дополнится событием `DELIVERED`.
- Ожидающие подтверждения живут в памяти одного экземпляра приложения ещё 10 минут после таймаута. При перезапуске эти попытки больше не принимают ACK. Уже сохранённые события доступны через REST.

### История пользователя

```http
GET /api/notifications?from=2026-10-31T00:00:00Z&to=2026-11-02T00:00:00Z&sort=DESC&size=20
```

Получатель определяется по сессии. Период включает `from` и исключает `to`. Поддерживаются `ASC` и `DESC` по времени события и размер страницы от 1 до 100. Если ответ содержит `nextCursor`, передайте его как `cursor` с теми же параметрами. Курсор привязан к текущей сессии. Страница может содержать меньше запрошенного числа событий при переходе между месяцами, поэтому ориентируйтесь на `nextCursor`.

### Попытки доставки уведомления

```http
GET /api/notifications/6b7b037d-d7a2-4b61-9923-3abd8159badf/attempts?month=2026-11&size=20
```

Запрос читает `attempts_by_notification_month` по идентификатору уведомления и месяцу UTC. Результаты доступны получателю. Для чужого уведомления и для месяца без попыток API возвращает `404`.

### Результаты доставки по каналу и статусу

```http
GET /api/admin/notifications/deliveries?channel=WEBSOCKET&status=UNCONFIRMED&month=2026-11&size=20
```

Маршрут доступен администратору. Он читает `deliveries_by_channel_status_month` по каналу, статусу и месяцу UTC. Оба запроса за месяц возвращают события от новых к старым. Для продолжения передайте `nextCursor` в параметре `cursor` с теми же фильтрами и размером страницы.
